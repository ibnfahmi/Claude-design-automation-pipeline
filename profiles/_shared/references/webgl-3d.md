# Rebuilding a 3D reference in the style preview

Used by the Design Agent in `scaffold and style preview` mode (and in the build) when the reference draws a WebGL scene (its `rendering` is `webgl`), or when the brief asks for a 3D hero. The scene is a React component in the project (for example `HeroScene.tsx`). You model the 3D elements yourself and write the shaders yourself: **no downloaded models, textures or images from the reference.** Everything is generated by code, so the project needs no assets beyond the 3D library.

Take the look only. Observe the reference's objects and shading from your screenshots, then build your own versions. Never copy its artwork, models, logos or copy.

## 1. Set up

- **Plain HTML projects (the default stack)** have no bundler and open from disk, so a module `import` or an npm package won't load. Create the Three.js file once with a one-off bundle step, and load it as a classic script: put `export * from 'three';` in a temporary entry file, run `npx --yes esbuild <entry> --bundle --format=iife --global-name=THREE --minify --outfile=scripts/vendor/three.js` (after `npm install three` in a scratch folder outside `code/`), keep only `scripts/vendor/three.js`, and add `<script src="scripts/vendor/three.js"></script>` before the scene script, which uses the global `THREE`. Check that the scene draws when the page is opened by double-click; if it doesn't, say so in the report. The rest of this file uses the `THREE.` names, which are the same either way.
- For a converted React or Next.js project, install Three.js with npm (`npm install three`, and `@types/three` for TypeScript). One `<canvas>` owned by the component, one `WebGLRenderer({ antialias: true, alpha: true })`. Create it in an effect, and dispose of the renderer, geometries, materials and textures when the component unmounts. Lazy-load the component so it doesn't slow the rest of the page.
- Cap the pixel ratio: `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`. Resize on window resize. Pause rendering when the tab is hidden.
- Check WebGL support first. If it is missing, or the context is lost, show the 2D CSS version of the hero and say so in the "Carried over" panel.
- `prefers-reduced-motion`: render one still frame, no camera moves, no floating.
- No network textures. Make any texture on a 2D canvas in code (gradients, noise, ray streaks) and wrap it in `THREE.CanvasTexture`.

## 2. Model the elements by eye

List the distinct objects in the reference screenshots, then write one small function per object that returns a `THREE.Mesh` or `THREE.Group`. Vary them with a seed so repeats don't look cloned.

| Look in the reference | Build it with |
|---|---|
| Faceted rock or asteroid | `IcosahedronGeometry(r, 1)`, then displace each vertex along its normal by seeded noise, then `computeVertexNormals()` and flat shading (`flatShading` or a toon shader) |
| Crystal, gem, shard | `OctahedronGeometry`, `CylinderGeometry(0, r, h, 6)` stacked mirrored, or a scaled `ConeGeometry` with 5-6 sides |
| Slab, bar, tile | `BoxGeometry`, optionally with bevelled corners via a slightly smaller inner box |
| Hexagonal or polygon prism | `CylinderGeometry(r, r, h, 6)` |
| Sphere with windows, visor, panel lines | `SphereGeometry`, plus slightly larger partial spheres or `RingGeometry` / `TorusGeometry` for rims, and inset boxes or planes for the windows |
| Ring, orbit line | `TorusGeometry` with a tiny tube radius, or `LineLoop` from a circle of points; a dashed look via a canvas texture |
| Terrain, ridge, foreground mass | A plane or wide box with seeded height displacement, kept low-poly |
| Light shaft, glow | A tall plane with an additive-blended gradient texture generated on a canvas |

Place objects in 3 to 5 depth layers (near, mid, far), with larger and darker near objects and smaller, hazier far ones, matching where the reference puts them. Use `InstancedMesh` for many repeated small shapes.

## 3. Shaders

Write `THREE.ShaderMaterial`s where the reference's shading can't be had from the built-in materials. Common cases:

**Toon (stepped) shading with a rim light**, for an illustrated, banded look. Pass the light direction in view space.

```glsl
// vertex
varying vec3 vNormal;
varying vec3 vViewDir;
void main() {
  vNormal = normalize(normalMatrix * normal);
  vec4 mv = modelViewMatrix * vec4(position, 1.0);
  vViewDir = normalize(-mv.xyz);
  gl_Position = projectionMatrix * mv;
}
// fragment
uniform vec3 uLight;     // light colour (the lit band)
uniform vec3 uShadow;    // shadow colour (the dark band)
uniform vec3 uRim;       // rim colour
uniform vec3 uLightDir;  // normalised, in view space
uniform float uSteps;    // 2.0 to 4.0 bands
varying vec3 vNormal;
varying vec3 vViewDir;
void main() {
  vec3 n = normalize(vNormal);
  float d = dot(n, normalize(uLightDir)) * 0.5 + 0.5;
  float band = floor(d * uSteps) / max(uSteps - 1.0, 1.0);
  vec3 col = mix(uShadow, uLight, clamp(band, 0.0, 1.0));
  float rim = pow(1.0 - max(dot(n, vViewDir), 0.0), 3.0);
  col += uRim * rim * 0.6;
  gl_FragColor = vec4(col, 1.0);
}
```

**Outline (inverted hull)**, for the drawn edge. Add a second mesh with the same geometry and `side: THREE.BackSide`, pushed outward along its normals:

```glsl
// vertex
uniform float uThickness;   // about 0.02 to 0.05 in object units
void main() {
  vec3 p = position + normal * uThickness;
  gl_Position = projectionMatrix * modelViewMatrix * vec4(p, 1.0);
}
// fragment
uniform vec3 uColor;        // the outline colour, a dark tone of the object
void main() { gl_FragColor = vec4(uColor, 1.0); }
```

**Other shader tools**, used only when the reference shows them:
- **Fresnel / rim glow** on glass, visors and crystals: the `rim` term above with a brighter colour and additive blending.
- **Depth fog or haze:** `scene.fog = new THREE.Fog(color, near, far)` for built-in materials, or mix toward a haze colour by view depth in your shader. Far objects fade into the background colour.
- **Gradient background:** a vertical gradient on the scene background or a large back plane, not a flat colour.
- **Film grain or dither:** a canvas-generated noise texture in a full-screen overlay with a low opacity (a CSS overlay is cheaper than a post-processing pass).
- **Emissive pulse** for glowing accents: a `uTime` uniform driving a slow sine on the colour.
- **Vertex wobble** for floating or breathing: displace by `sin(uTime + position.y)` along the normal, a small amount.

Pick the shading from what the screenshots show (banded and outlined, smooth and glossy, matte and grainy). Don't add effects the reference doesn't have.

## 4. Camera and motion

- Define a **camera pose per step** (position and look-at target) from the reference's interaction steps. On a click, animate between poses with the measured duration and easing. Implement the easing from the measured `cubic-bezier(x1, y1, x2, y2)` with a small bezier solver, not a built-in ease.
- Add slow rotation and float to objects with different speeds and phases, and gentle pointer parallax (move the camera a few percent toward the pointer, damped).
- The headline and button live in HTML above the canvas and animate with CSS transitions in sync with the camera.

## 5. Compare and refine (up to three passes)

When a browser is available, open the running preview route in the built-in browser at the same viewport size as the reference screenshots, wait for it to settle, and take a screenshot. Compare it with the reference screenshots on:

1. Silhouettes of the key objects (their basic shapes and proportions)
2. Shading style (banded or smooth, outlined or not, rim light) and the value balance between light and dark
3. Palette in the lit, shadowed and background areas
4. Depth layering, haze and scale
5. Composition: where objects sit, and the empty space around the text
6. The camera result after each click

Fix the largest difference first, and repeat up to three times. Stop earlier when the remaining differences are small. Report what still differs in the "Carried over" panel and in `SIGNATURE_USED`; never claim a match you haven't checked.

## 6. Keep it light

The preview is a style check, not the product. Aim for tens of objects, not hundreds, a steady frame rate on a laptop, and a few hundred lines of code. If a piece of the reference's look would take a lot of work for little gain (a complex terrain, a full character), approximate it more simply and say so.

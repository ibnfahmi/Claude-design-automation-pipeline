# Figma export: a spec from the real page, built natively

Used by the Handoff Agent when it builds the Figma file from the running app. The connector's capture tools (`generate_figma_design`, `html_to_figma`) produced frames full of nested wrappers with absolute positions, half-loaded elements and off-grid spacing. The export now **builds the frames itself from a measured spec**, so the layout, fonts and spacing are exactly what the page renders and what auto layout can express. The capture tools stay only as a fallback.

## 0. The spec-driven path (default)

1. **Tools (once, with consent, before anything is built).** The Orchestrator does this in the `to-figma` skill (step 4), before it starts the Handoff Agent, and verifies it with `node -e "const r=require('module').createRequire(process.cwd()+'/package.json');r('playwright-core');r('pngjs');r.resolve('pixelmatch');console.log('tools ok')"` run in the tools folder (`tools ok`). The Handoff Agent repeats that check first thing. The Handoff Agent cannot talk to the user: if `figma_tools` is declined or the packages are missing, it returns `BLOCKED: <reason and the options>` and the Orchestrator asks the user; it **stops** only when the tools were accepted but the check still fails (for example in a resumed session). Never start measuring or building with the packages missing. Check `~/.claude/design-pipeline/tools/figma/node_modules` for `playwright-core`, `pngjs` and `pixelmatch`. If missing, ask once (AskUserQuestion, header `Figma tools`): *"Install three small open-source helper packages (playwright-core, pngjs, pixelmatch) used to measure the pages and compare screenshots? They run on your computer and use the Chrome or Edge you already have, so there is no browser download."* **Yes (Recommended)**: "Frames are built from a measured spec: real auto layout, SVG icons, exact text widths." / **No, ask me about the capture tool**: "Quality drops. Icons can turn into black squares, text gets clipped and spacing leaves the scale. Every such frame is labelled 'capture fallback' and you'll be offered a rebuild later." On yes, in that folder run `npm init -y` and `npm install playwright-core pngjs pixelmatch`. Save the answer in the state file (`figma_tools`).
2. **Extract the spec at each frame's own size.** Write `frames.json` from `design-manifest.json`: for every frame, its slug, its route and its **own viewport** (the width and height chosen in preflight for that platform: for example Desktop 1440 or 1920, Tablet 768, Mobile 375 or 390, a kiosk or TV stage at its exact pixel size; never a fixed 1440). Run `node <assets>/figma-spec/extract-spec.mjs --base <dev_url> --frames frames.json --out figma-spec`. For each frame it opens `/frames/<slug>?capture=1` at that width, waits for `document.fonts.ready`, the capture-ready flag, images and scroll-triggered effects, finishes animations, passes a stability check, saves the full-page **reference screenshot** (`<slug>@<w>.png`) and the **spec** (`<slug>@<w>.json`), and an `index.json` with the fonts in use. Each screen size is extracted and built as its own frame. Without the tools, run `spec-extractor.js` in the built-in browser (`javascript_tool`) after the same waiting, and take the reference screenshot with the browser.
3. **Pin the fonts before building** (section 3b below).
4. **Build each frame with `figma-builder.js`** (section 2b below).
5. **Compare and iterate, screen by screen** (section 4b below).

If the extraction or the build is not possible (no tools, the page can't be opened, a font can't be pinned), **do not fall back silently.** Say why in one line with the one fix (install the tools, start the app, pin or substitute the font), then return `BLOCKED: <reason and the options>` so the Orchestrator asks the user (AskUserQuestion, header `Capture fallback`): **Fix it and retry (Recommended)** / **Use the capture tool for these frames** ("Lower quality: icons, text widths and spacing can break. They are labelled 'capture fallback'."). The Handoff Agent uses the capture tool only after the Orchestrator passes the user's yes, with sections 1 and 2 below.

**Tag every frame by how it was built.** `figma-builder.js` sets `pipeline:source = spec` (and `pipeline:hash`) on each top-level frame it builds, as **shared plugin data** (`setSharedPluginData('pipeline', 'source', 'spec')`; this Figma host rejects the plain `setPluginData`). A frame built by the capture tool gets `pipeline:source = capture-fallback` through a short `use_figma` call (`node.setPluginData`), and is listed in the report with the reason. Re-exports use these tags (`figma-structure.md`, "Re-export").

## 1. Final state (needed by the spec path and by the capture-tool fallback)

Capture happens only when the page has finished loading and animating. Never take a frame while anything is still moving.

**Capture mode.** Every frame route accepts `?capture=1` (the Design Agent builds this into every project; see `code-conventions.md`, "Capture mode"). In capture mode the page shows its **final, settled state**: entrance animations and transitions finished, reveal-on-scroll items already revealed, counters at their final value, scroll-linked and "active step" effects in their resting state, carousels and marquees stopped at the first position, lazy images loaded, fonts ready, videos on their poster frame, and no transform offsets left over. When it is settled the page sets `document.documentElement.dataset.captureReady = "true"`.

**Before each capture** (resize the browser to the frame's viewport first, then open `/frames/<slug>?capture=1`):
1. Wait for `data-capture-ready="true"` (up to 30 s). If the page has no capture mode (an existing project), do the steps below by hand.
2. Wait for fonts and images: `await document.fonts.ready`, then every `<img>` is `complete` with a non-zero `naturalWidth` (`img.decode()`), background images loaded, the network quiet for about 1 s.
3. **Trigger and finish everything that depends on scroll or time:** scroll the page slowly to the bottom and back to the top (a viewport height at a time, about 400 ms apart) so reveal-on-scroll, lazy loading and counters run; wait for transitions to end; finish running animations (`document.getAnimations().forEach(a => a.finish())` for finite ones) and stop infinite ones at their first frame; remove leftover offsets (a reveal that still has `opacity < 1` or a non-identity `transform` after this is **not final**: fix it in capture mode, don't capture it).
4. **Stability check:** read the bounding boxes, opacity and transform of all visible elements twice, 600 ms apart, with no scrolling in between. If anything changed, wait and check again (up to three times). Never capture while it changes.
5. **Verify with a screenshot** of the settled page and look at it: no half-visible text or cards, no faded steps that should be fully drawn, no spinner or skeleton unless that is the state being captured, no cut-off content at the bottom (scroll to the end, the full page height is captured), no overlay such as a cookie banner or dev toggle.

State frames (hover, focus, pressed, open menu, error) are captured **after** triggering the state and waiting for its transition to end, with the same stability check.

If an element is still not in its final state after capture mode, that is a **code defect** (report it for the Design Agent) and, for the file, build the element in its final state natively instead of capturing the mid-state.

## 2. Structure: from captured wrappers to auto layout (capture-tool fallback only; the builder does this by construction)

Captured frames often arrive as deep stacks of wrapper frames with absolute positions, empty placeholders and transform wrappers (names like `Container`, `Article:transform`, `Placeholder for Article`, `Italic Text`). Fix them in a **structure pass** on every captured frame, working from the leaves up. Keep the visual result the same.

1. **Clean:** delete empty, zero-size, hidden and placeholder nodes (`Placeholder…`, `…:transform` wrappers with no styling, empty containers); delete duplicated text nodes.
2. **Flatten:** a frame with a single child and no fill, stroke, effect, radius or padding is removed and its child moved up. Merge nested frames that only repeat the same layout.
3. **Apply auto layout to every frame that has two or more in-flow children.** Infer from the children's positions:
   - children side by side (their vertical ranges overlap): `layoutMode = HORIZONTAL`; stacked: `VERTICAL`;
   - a grid of cards or tiles: an outer `VERTICAL` frame of `HORIZONTAL` rows, or one `HORIZONTAL` frame with `layoutWrap = WRAP` when the items share a fixed size;
   - set the item spacing (gap), the padding (from the distance between the frame's edge and its children), and the alignment on both axes (start, center, end, space between) from how the children actually sit.
4. **Sizing, so it behaves like the code:** the page root is `FIXED` at the viewport width. Text, buttons, chips and icons **hug** their content; columns, cards in a grid, input fields and section containers **fill** the available width (`layoutGrow = 1` or `layoutAlign = STRETCH`); images keep their aspect ratio (fixed size or fill with a locked ratio). Never leave a frame as fixed width and height just because the capture gave it a size (this applies to capture-fallback frames only; frames built from a measured spec keep their measured container sizes).
5. **Absolute position only where it is truly an overlay:** a badge on a card corner, a decorative illustration or background shape, a sticky or fixed element, a tooltip. Everything else is in the flow. For an overlay use `layoutPositioning = ABSOLUTE` with the right constraints (pinned to the edge it sits on), not loose coordinates.
6. **Name every layer** for what it is (`Header`, `Nav / Link`, `Card / Challenge`, `Card / Title`, `Stat / Participants`, `Button / Primary`), never `Frame 123`, `Group 4`, `Container`, `Italic Text` or `Article:transform`. Repeated elements become **components with variants** and instances (cards, buttons, chips, list rows, form fields).
7. **Check:** after the pass, list every frame that still has more than one in-flow child and no auto layout, and every absolutely positioned node that is not an intended overlay. Fix them, or report them. The target is no unintended absolute positions and no unintended fixed sizes.

**If a frame is too broken to fix** (for example the capture produced a flat pile of absolutely positioned nodes), **rebuild it natively from the DOM**: run a script with `javascript_tool` on the real page that walks the visible elements and returns a JSON tree (tag, role, text, computed `display`, `flex-direction`, `gap`, padding, alignment, width, height, colours, borders, radii, shadows, image sources), then create the frames in Figma with `use_figma`, mapping `display:flex` directly to auto layout (direction, gap, padding, alignment) and `display:grid` to rows of auto-layout frames. This is slower, and it gives the cleanest result. Prefer it for any component whose structure is mostly flex or grid.

## 2b. Building from the spec with `figma-builder.js`

`figma-builder.js` is a template for `use_figma`. Load the `figma-use` skill first and follow its rules. For each frame, split the spec's root into **sections** (its top-level children, such as header, hero, each content section, footer) so every call is small and safe to retry. For each call replace the three placeholders in the three `const` lines at the top of the template (`SPEC`, `FONTMAP`, `OPTS`) with JSON, and send the text as the `code`:
- **First call:** create the top-level frame for the screen (the spec root without its children, `parentId: null`, its `name` from the manifest and a free position on the page). Return its id. The builder does not create layout grids: after this first call, set `layoutGrids` on the top-level frame with a short `use_figma` call (section 3).
- **Next calls:** one per section, `parentId` = that frame's id, in page order. The builder returns the node ids, counts, the images to fill, missing fonts, approximations and spacing deviations.
What the builder does: **flex becomes auto layout** (direction, gap, padding, justify, align, wrap, grow and stretch); **grid becomes a vertical frame of horizontal rows**; a block with stacked or side-by-side children becomes an inferred auto-layout stack; absolute positioning is kept **only** for real overlays (`layoutPositioning = ABSOLUTE` with the right constraints); containers keep their **fixed sizes** and only buttons, pills and inline-flex items hug their content; text gets its pinned font, size, line height, letter spacing, case, decoration, alignment, truncation and line clamp, and mixed-style text keeps its runs; fills, gradients, borders, radii, shadows and blurs are applied; inline SVG becomes vector nodes; spacing is snapped to the scale and bound to the `Space/*` variables, colours to the colour variables when they match a token. Images become named placeholders.
**Images:** after the sections are built, fill each placeholder: download the image sources the builder returned (for example with `curl` from the running app) and upload them with the connector's `upload_assets` (`nodeIds` set to the placeholder ids, up to 60 per call). Don't pass image bytes through `use_figma`. Two kinds need no download or are handled for you:
- **SVG images** (`<img src="*.svg">`, which `upload_assets` cannot fill): the extractor reads the SVG's markup and returns the image as an inline vector node (icons, logos, decoration), so it is drawn by the builder like any other icon and never becomes a grey placeholder. A CSS `filter: brightness(0) invert(1)` on such an image is applied to its colours.
- **Video and canvas:** the extractor saves each one's pixels with everything else hidden, as `figma-spec/assets/<slug>@<w>.media<n>.png`, and the builder's `images` list gives that path as `file`. Upload that file to the placeholder instead of the `src` (a video's source is not an image).

Inputs, textareas and selects show their value or placeholder as text inside their box (the placeholder in its own colour).
**Variables first:** before the first call create the variable collections (`Space/*` from the scale, colours and radii from `tokens.css`, plus typography as `Type/*` variables), return their ids, and pass them in `OPTS`.
**Typography is exported as variables.** Create a `Type` variable collection from the type styles in `tokens.css`: for each style (`Type/<style>/size`, `/line-height`, `/letter-spacing` as FLOAT variables, `/family` and `/weight` as STRING variables, scoped to the matching text properties) and bind every text node's font size, line height, letter spacing, font family and style to them (`setBoundVariable`) in a pass after the sections are built, loading each font first. Also create a Figma text style per type style. Never leave type as raw values; report `TYPE VARIABLES: <n> styles, <n> text nodes bound`.

## 2b+. Build with the runner: the builder and the specs travel as files, not as text in the calls (default)

Pasting the 27 KB builder and a spec into every `use_figma` call is the most expensive thing an export does (a test measured about 9,000 tokens of input per call), and every call also counts against the Figma MCP tool-call limit of the seat. So the builder, the runner and the specs are sent **once, as files**, and each build call is a bootstrap of about 400 characters. `figma-spec/pack-payload.mjs` and `figma-runner.js` do this; both host features it needs were seen working in a real export: `upload_assets` carries a file into the Figma file, and the plugin sandbox can run code read from a text node (`new AsyncFunction`).

1. **Pack** (after the extraction and `state-delta.mjs`, with the pages created): `node <assets>/figma-spec/pack-payload.mjs pack --dir figma-spec --frames frames.json --pages pages.json --deltas figma-spec/state-deltas.json --fonts fontmap.json --opts opts.json`. `pages.json` maps each feature page name to its Figma page id; `fontmap.json` is the pinned fonts (section 3b); `opts.json` is `OPTS` (spacing and colour variable ids, `fixedContainers`). It writes `figma-spec/payload/*.svg` (the builder, the runner, the plan and one file per frame; overlay-only states are packed as overlay jobs) and `manifest.json`. Each SVG holds the payload as base64 in one text element.
2. **Create a page named `Payload`** in the Figma file (one `use_figma` call, remember its id), then **upload**: one `upload_assets` call with `count` = the number of files in `manifest.json` and `currentPageId` = the Payload page; it returns one submit URL per file. Then `node <assets>/figma-spec/pack-payload.mjs post --dir figma-spec/payload --urls '[<the submit URLs, in order>]'`: it POSTs each file with its file name as the layer name and writes `placed.json`. Each file becomes a frame on the Payload page with one TEXT node holding the data.
3. **Build with the runner.** Every build call is the bootstrap in the header of `figma-runner.js` (about 400 characters: it reads `runner.js` from the Payload page and runs it with `{payloadPage, from, budgetMs}`). The runner builds the plan's frames one after another, a frame section by section (the first section creates the top-level frame without its children, the next ones append the page's top-level children), or an overlay-only frame in one step, stops starting new frames after `budgetMs` (30,000 by default; the sandbox limits a call) and returns `next` and `done`. Call again with `from = next` until `done` is true. It returns the frames built (slug, node id, size), the images still to fill, missing fonts, approximations and errors; a frame that failed is listed in `errors` and can be rebuilt with `only: [slug]`.
4. **Fill the images.** The runner's `images` list is grouped by picture (one entry per source with every placeholder id, and `file` for a video or canvas). Pass `compact: true` in the runner's `RUN` to get one text line per picture instead of JSON (save it as `images.txt` and pass `--base <the app address>`), or save the JSON as `images.json`, then `node <assets>/figma-spec/pack-payload.mjs fill-plan --dir figma-spec --images images.json --assets "<the app's assets folder>"`: it finds each picture's local file, writes `fill-plan.json` and prints the `nodeIds` in the order the upload needs. One `upload_assets` call with that `nodeIds` (up to 60 per call) returns the submit URLs; `pack-payload.mjs fill-post --plan figma-spec/payload/fill-plan.json --urls '[...]'` posts every file. SVG sources are never filled (the extractor draws them as vectors); a picture with no local file is listed as `missing`.
5. **At the end, delete the `Payload` page** (the finish step), so the file holds only the design.

**Before the export:** `node <assets>/figma-spec/export-lint.mjs --dir code` lists the patterns that will drift (see "Export-friendly authoring" in `code-quality.md`); tell the user which screens they affect.

**Frames that need interaction.** A frame in `frames.json` may carry `steps` (click, hover, fill, select, press, wait, scroll, eval) that bring the page to the state before it is measured, for example opening a dialog or filling a form; a step that fails is listed as `stepErrors` and the frame still exports. A frame may also carry `local` (settings such as the language, applied before the page loads).

**Layout is read from the page's own properties, not guessed.** The spec carries `justify-items`, `justify-self`, `align-items`, `align-self`, the row track heights, `position` and `z-index`; the builder aligns grid items from them and orders layers the way CSS paints (positioned above non-positioned, by z-index, then page order). When a frame is off, find which property was not carried instead of nudging the result. The runner returns a `drift` figure per frame (with `tall` and `firstTall`: texts whose built height differs from the measured one; a text box measured by the browser is the font's content area, so a few pixels on single lines are normal, a whole line or more means a different wrap or a clamp) (texts built more than 8 px from where the page measured them), a free check before any screenshot.

**What the extraction gives the runner** (so nothing has to be fixed by hand): `extract-spec.mjs` applies a frame's `local` settings (for example the site's language) before the page loads; draws `<img src="*.svg">` as inline vectors, keeping a mirrored arrow mirrored; saves the pixels of a video or canvas, after pausing videos so the reference screenshot shows the same frame; and drops hair-thin gradient strips (animated link underlines) that would otherwise become boxes. An element painted by a `conic-gradient` or a CSS mask (a progress ring made of a styled `span`) is saved as a picture of its own pixels and used as its fill, children stay layers; an SVG Figma cannot import (dashed strokes such as progress rings, masks, filters, patterns, embedded bitmaps, `foreignObject`, or over 24,000 characters) is saved as a picture instead; one off the screen that cannot be captured stays a placeholder and is reported under `missing`. `fill-plan` downloads remote pictures and uses FIT for `contain` and FILL otherwise.

**Fallback.** If the upload or the code from the file is refused by the host (the first runner call fails with an error about `AsyncFunction`, `atob` or a missing payload), build as section 2b describes, with the builder and the section pasted into each call, and say so in the report. A change to the builder or a spec after packing means packing and uploading again.

## 2c. Library first (`figma_library = instances`)

The code's components are the library. Every reusable component's root carries `data-component="Name"` (`code-conventions.md`), and `spec-extractor.js` records it as `comp` together with `sig`: a short hash of the node's structure and look (fills, borders, radii, layout, text styles), **not** its text, size or images. The same `comp|sig` is the same Figma component.

1. **Collect.** Walk every `<slug>@<w>.json` and group nodes by `comp|sig`. A group used in two or more places, and every component of the app shell and navigation, becomes a library component; a component used once stays a plain frame. Pick the first occurrence as the canonical one. If fewer than three components are found, say so: the code probably lacks `data-component` roots (report it for the Design Agent).
2. **Order.** Leaf components first (those that contain no other `comp|sig` node), so a larger component is built with instances of the smaller ones inside it. After each component is built, add it to the `components` map you pass to the next call.
3. **Build each component** on the `Components` page with `figma-builder.js`, using `SPEC.asComponent = { name: "<Component> / <Variant>" }`. The builder builds the canonical spec as a normal auto-layout frame and converts it with `figma.createComponentFromNode`, tagging it `pipeline:component` and `pipeline:sig`. Variant names come from the frame states where there are some (`Default`, `Pressed`, `Error`), otherwise `Variant 2`, `Variant 3`.
4. **Group variants.** Components with the same `comp` and different `sig` are combined into one component set with `figma.combineAsVariants` (property `Variant`). Component ids stay valid after combining.
5. **Build the screens.** Pass `OPTS.components = { "Button|1a2b3c": { id: "<component id>" }, ... }`. A node whose `comp|sig` is in the map becomes an **instance**: the builder creates the instance, sets each text to the node's own text (fonts loaded first), queues image fills for the instance's image rectangles, sets the measured size and the same sizing rules as a frame. If the text or image counts differ from the component, it discards the instance, builds the node as a frame and reports `component mismatch`. A missing component id is reported as `component not found`.
6. **Report and check.** Components built, variants, instances created, nodes built as frames with the reason. The Components page shows `Used in <n> frames` under each component. The screenshot comparison (section 4b) and the checks in section 4 apply to screens built from instances exactly as to plain frames.

## 2d. Overlay states: only the overlay, or the overlay on a cropped clone of the base

A dialog, menu, dropdown or search open over a page is usually the same page as an already-built frame, with the page scroll-locked behind it: the state frame is viewport-sized (for example 900 px tall) while the base frame is the full page. Building the whole page again for each of them is the most repeated work in an export. So these states are exported **overlay only**, always and without a question: the frame holds just the scrim and the dialog (or menu, drawer, dropdown), with no page behind it. The fallback is **the overlay on a cropped clone of the base frame**, never a full rebuild.

1. **Find them (after the extraction).** Run `node <assets>/figma-spec/state-delta.mjs --frames frames.json --dir figma-spec --out figma-spec/state-deltas.json`. For each state frame it reports the base frame it overlays (an earlier frame of the same page and width that is not itself an overlay), the crop height, the width, the overlay nodes (the top-most fixed or absolute subtrees that the base page does not already have, with positions in page coordinates) and the `compareBox`. A state is `reusable` (overlay-only) when its non-overlay content inside the viewport matches the base within a small tolerance (5% of the nodes, at least 2). When the page behind it differs a little (up to 25%: for example the header changes for a signed-in user) it is `near`: there is no exact base, so it is exported as the overlay on a cropped clone of the closest base. Anything further away is a different screen, not an overlay state, and is built in full like any other frame. Keep the result in `figma-spec/state-deltas.json` (each frame's `overlay` mode, `base` and `compareBox`).
2. **Build the overlay-only frame.** One `use_figma` call with the builder: `overlayOnly: true`, `width`, `cropHeight` (the state's viewport size) and `add` (the overlay nodes from `state-deltas.json`), plus `name`, `x`, `y`, `pageId` and `hash`. The frame is transparent, clips its content, and holds just the scrim and the dialog at their page positions. The scrim keeps its fill, and its `backdrop-filter` becomes a background-blur effect, but with no page inside the frame there is nothing to blur, so the blur is not visible on the canvas; say so in the report. No base page is needed, so the order of the frames does not matter.
3. **Compare only the dialog area.** `compare-shots.mjs --crop <compareBox>` with the frame's `compareBox` (the box around the dialog; the page behind it is not in the frame, so the rest is not compared).
4. **Fallback: the overlay on a cropped clone of the base.** When an overlay-only frame fails its comparison, or the state is `near`, build the frame as a clone: one `use_figma` call with the builder, `cloneOf` = the node id of the built base frame (kept from its build), `cropHeight` = the state's height, `add` = the overlay nodes, plus `name`, `x`, `y`, `pageId` and `hash`. The builder clones the base, resizes the clone to the crop height with **clip content** on, builds the overlay as absolute children on top, and tags the clone `pipeline:clonedFrom`. The base must be built first, so build base frames before the states that need them; if the base's node id isn't available yet, build the base first. A clone is compared with its whole reference screenshot (section 4b). If the clone also fails, do not rebuild the frame in full: list it as failing in `COMPARE` with the worst regions and the cause, and let the Orchestrator decide.
5. **Report** how many frames were exported overlay-only, how many on a clone, how many failed, and the turns saved.

## 3. A grid and a spacing system that developers can trust

The Figma file must follow a system even when the code doesn't. Snap to it; don't copy stray values.

**Spacing scale (4 px base, 8 px rhythm):** `0, 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96, 128`. Use these for **item spacing, padding and margins**. Create them as Figma variables `Space/4`, `Space/8` … and **bind** every gap and padding to a variable. If the project's design system defines its own scale (for example `tokens.css`), use it instead, as long as it is a regular scale; say so in the report.
- **Snap each measured value to the nearest scale step** (ties go to the larger step): 10 is a tie between 8 and 12, so it becomes 12 (9 becomes 8, 11 becomes 12), 46 becomes 48, 23 becomes 24, 52 becomes 48, 60 becomes 64. A value of 1 or 2 px that is a hairline border or optical nudge is not spacing.
- **Sizes:** fixed widths and heights of components (buttons, inputs, avatars, icons, cards) are multiples of 4 (icons 16, 20, 24, 32, 40, 48). Line heights are multiples of 4 and come from the type scale. Radii come from a short scale (`0, 4, 8, 12, 16, 24, full`).
- **Alignment:** left edges, baselines and centres line up; items in a row share a top or centre line; repeated cards have equal widths and heights.

**Layout grids on every top-level frame**, set with `layoutGrids` in a short `use_figma` call after the first builder call (the builder does not create them), by platform (use the project's real container and gutters if the code states them, otherwise these defaults):
- **Desktop web and desktop app:** 12 columns, gutter 24, margin 80 (or the container's side margins), content max width as in the code, snapped to the scale.
- **Tablet, including iPad mini (744), and any width from 744 to 1279:** 8 columns, gutter 24, margin 32.
- **Mobile:** 4 columns, gutter 16, margin 16.
- **TV, kiosk and slides:** the project's own container, no column grid.
- Add a baseline grid of 8 on frames with text-heavy layouts if the design system uses one.
Section and column widths follow the columns. Content that sits off the grid on purpose (full-bleed images, backgrounds) is marked as such.

**Deviations are reported, not hidden.** Where snapping moved a value by 3 px or more, or a layout could not follow the grid, list it in the result under `DEVIATIONS` (where, value in the code, value in Figma); it is not drawn in the file. That list tells developers where the code drifts from the system, and the Orchestrator can offer a revision round that aligns the code with the scale.

## 3b. Pin the fonts before the import

1. Take the fonts the extractor found (`index.json`: family, weight, style, count, and whether the page had them loaded).
2. In one read-only `use_figma` call run `await figma.listAvailableFontsAsync()` and map every `family | weight | style` to an **exact Figma font** (family and style name; verify the style string from the list, such as `SemiBold` against `Semi Bold`, never guess). Load each with `figma.loadFontAsync` in that call and return the mapping (`FONTMAP`) and any font that is missing.
3. **Missing fonts are reported before any frame is built**: name the font, the closest available substitute, and what it affects. Continue with the substitute only after saying so (the Handoff Agent doesn't stop to ask unless the user can fix it in a minute, for example by enabling the font in Figma). Never let Figma substitute silently.
4. Report the pinned fonts in the result (`FONTS`).

## 4b. Compare each screen with its reference, and iterate

**This runs by default, on every export, for every frame built from a measured spec, with no question and no way to skip it.** The only consent in the whole path is the one-time install of the helper packages. If the packages are not installed the export does not get this far (section 0): it returns `BLOCKED` and the Orchestrator asks, it does not build without comparing. Frames built by the capture-tool fallback cannot be compared (no pngjs/pixelmatch): list them under `COMPARE` as `not compared (capture fallback)`; that is not a defect.

**Keep the turns down.** Compare the frames of a batch in one command (a loop over `compare-shots.mjs` in a single Bash call, printing one line per frame), read only those numbers, and look at images only for failing frames (their diff picture and the two screenshots). Do not open or screenshot a frame that passed. Build several simple frames in one `use_figma` call (up to about 5 frames or 6,000 characters of code) and upload their images in one `upload_assets` call; one frame per call only when it is large or fragile.

For every frame, after it is built (and its images filled):
1. Take a screenshot of the Figma frame at 1x (`get_screenshot`, or `await frame.screenshot({ scale: 1 })`), download it to `figma-spec/<slug>@<w>.figma.png`.
2. Run `node <assets>/figma-spec/compare-shots.mjs --a figma-spec/<slug>@<w>.png --b figma-spec/<slug>@<w>.figma.png --out figma-spec/<slug>@<w>.diff.png`. It returns `pass` (true or false, and the exit code says the same), the difference percentage and the worst regions (x, y, width, height). A frame **fails** when the whole-screen difference is above 2%, when any grid cell differs by more than 10% (this catches a single wrong-sized button or icon that the whole-screen number hides) or when the sizes differ.
3. If the size differs (`sizeMismatch`) fix the frame size first. If the frame fails (`pass: false`), look at the worst regions in the diff image and the two screenshots, find the cause (a wrong gap or padding, a fixed size where it should fill, a missing font or weight, a missing image, a shadow, a gradient direction), fix **those nodes** with a targeted `use_figma` call, and compare again. **Up to three passes per screen.** Don't rebuild the frame.
4. A frame is returned only when it passes. After three passes, a frame that still fails is returned anyway but is **listed as failing** in `COMPARE` with its worst regions and the cause you found, never silently. Record each screen's final difference and any residual issue (for example "gradient approximated", "font substituted"), and report them in the result.
Snapping to the spacing scale moves things by a few pixels, so a small residual difference is expected; unexplained large regions are not.

## 4. Check before returning

- Every screen has been compared with its reference screenshot (final difference reported, three passes at most), which is also the proof that it matches the running app in its **final state** (differences only from snapping, none larger than a few pixels): do not take a further screenshot of every frame, only one of each page's overview, and no frame shows a half-faded, shrunken or sliding element.
- No default or tool-made layer names; repeated elements are component instances.
- Every frame that holds more than one in-flow child uses auto layout; no unintended absolute positions, and no fixed sizes other than the measured containers; absolute positioning appears only on intended overlays; padding and gaps are bound to the spacing variables and are all on the scale; layout grids are set on every top-level frame.
- The deviations are listed in the result.
